#### Fixes

- Brightness keys (`XF86MonBrightnessUp` / `XF86MonBrightnessDown`) now actually change the panel backlight. Two bugs shipped with the 1.2.0 Go backend: `brightnessctl` was invoked without the `%` suffix (so `brightnessctl s 60` drove an AMD panel to 0.015 % instead of 60 %), and the CLI keybind path sent the value as a JSON string that the daemon silently dropped. The topbar slider worked but mapped to the wrong level; the keybinds did nothing. ([#227](https://github.com/Axenide/Ambxst/issues/227), [#228](https://github.com/Axenide/Ambxst/issues/228))
- Brightness detection on internal laptop panels no longer skips the read. A typo in `Brightness.qml`'s `Component.onCompleted` left `initialize()` unreachable on `eDP` / `LVDS` / `DSI` screens, so the slider and idle restore did nothing on most laptops. ([#228](https://github.com/Axenide/Ambxst/issues/228))
- The slider value, OSD indicator and idle-restore hook now follow the panel backlight accurately instead of staying frozen after the first set.

#### Changed

- Brightness control is now delegated to `axctl`, alongside `darkmode` and idle. The buggy Go-side service and the dead `BrightnessSlider.qml` are gone. The `ambxst brightness …` CLI stays as a thin shim, so existing scripts keep working.
- Default keybinds and the idle listener (`XF86MonBrightnessUp` / `Down`, the 150 s pre-lock dim) now invoke `axctl brightness …` directly instead of routing through the shim — one fewer fork per keypress, one less process to spawn on resume.

#### Removed

- `backend/pkg/svc/brightness/` (~250 lines of buggy Go) and `scripts/brightness_list.sh` (legacy bash that wrote broken multi-VCP entries, see [#29](https://github.com/Axenide/Ambxst/issues/29)).
- `modules/bar/BrightnessSlider.qml` — dead component, never imported.

#### Added (axctl)

- New `axctl brightness` subcommand: `list`, `get`, `set`, `adjust`, `save`, `restore`. Values are normalized 0..1.
- `Event.BrightnessChanged` is broadcast on the subscribe channel whenever a set or adjust succeeds, so other clients (sliders, OSD, external scripts) can react without polling.

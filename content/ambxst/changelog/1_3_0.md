# AMBXST MODS

Ambxst 1.3.0 ships a **native mod manager**, contributed by [flathead](https://github.com/flathead) in [PR #230](https://github.com/Axenide/Ambxst/pull/230). Community work no longer has to wait in the review queue: mods can be installed, configured, updated, reordered, disabled and removed straight from Settings, without maintaining a fork.

#### How it works

- Mods are declarative packages: an `ambxst.mod.json` manifest plus patches and/or overlay files.
- Install from a local directory, an archive, a Git URL, or a GitHub package-directory link.
- Enabled packages are composed onto a clean Ambxst source tree into immutable generations, activated atomically, with an eight-second startup health window, rollback and recovery.
- Dependencies are resolved and installed in topological order, and load order is drag-and-drop.
- Strict manifest and settings schemas, with per-mod declarative settings exposed through a native QML API.
- No polling and no background workers. Network access and builds only happen after an explicit action, and a failed build never touches the running shell.
- Every operation is also available through the `ambxst mods` CLI.

Mods run with your user permissions, exactly like the rest of Ambxst. Packages are installed disabled, and a trust prompt shows author, license and declared permissions before anything runs. Read [PR #230](https://github.com/Axenide/Ambxst/pull/230) for a full walkthrough: it is the best documentation of how the system works and why.

#### Where to get mods

The first collections are already out: [flathead/ambxst-mods](https://github.com/flathead/ambxst-mods) and [vinatic/Ambxst-Mods](https://github.com/vinatic/Ambxst-Mods). Paste a package link into Settings → Mods and you are done.
